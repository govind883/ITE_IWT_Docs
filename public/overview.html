🔐 1. Authentication & Authorization

🔐 A. Login Process

Step-by-Step Login Flow:

  1. User Enters Credentials:
    • Open login page
    • Enter email/username
    • Enter password
    • Click "Login" button
  2. System Validates Credentials:
    • Checks email exists in database
    • Verifies password matches (encrypted)
    • Checks user account status (Active/Inactive)
    • Returns error if any validation fails
  3. Password Validation:
    • Password stored encrypted in database
    • Entered password encrypted and compared
    • Bad credentials returned if no match
    • Account security maintained (no plain text storage)
  4. User Status Check:
    • Active users: Can login
    • Inactive users: Access denied (account disabled)
    • Suspended users: Access denied (pending review)
  5. Load User Details:
    • Fetch user information from database
    • Load user roles and permissions
    • Load department and team assignments
    • Load user profile data

Error Handling:

  • Invalid Email: "User not found" error
  • Wrong Password: "Invalid credentials" error
  • Inactive Account: "User account is disabled" error
  • System Error: "Authentication failed, please try again"

🎟️ B. JWT Token Generation & Management

What is JWT Token?

  • JWT = JSON Web Token
    • Secure token representing logged-in user
    • Cryptographically signed by server
    • Cannot be forged (only server can create)
    • Contains user information encoded inside
  • Token Structure:
    • Header: Algorithm and token type
    • Payload: User data (ID, email, roles, org)
    • Signature: Server's digital signature

Token Generation Process:

  1. After Successful Login:
    • Server creates JWT token
    • Encodes user ID, email, roles into token
    • Signs token with secret key
    • Returns token to client
  2. Token Content Includes:
    • User ID (unique identifier)
    • Email address
    • Organization ID (tenant)
    • Roles and permissions
    • Issue time (when created)
    • Expiration time (when expires)
  3. Example Token Usage:
    • Client receives token after login
    • Stores token in browser session/local storage
    • Includes token in every API request
    • Server verifies token before processing request

Token Expiration:

  • Token Lifetime:
    • Typically valid for 24 hours
    • Configurable per organization
    • Can be shortened for sensitive operations
  • After Expiration:
    • Token no longer accepted by server
    • User must login again to get new token
    • Session data cleared
    • Access denied until re-authentication

📋 C. Session Management

What is a User Session?

  • Time period when user is logged into system
  • Starts when user successfully logs in
  • Ends when user logs out or token expires
  • Each session has unique token

Session Data Stored:

  • User Information:
    • User ID
    • Email
    • Full name
    • User role
    • Department
  • Permissions:
    • Modules user can access
    • Operations allowed (Create, Edit, Delete, Approve)
    • Data visibility level
  • Organization Context:
    • Organization ID (tenant)
    • Organization name
    • User's team/department

Session Activity Tracking:

  • Activity Monitored:
    • Login time and date
    • Last activity timestamp
    • IP address of user
    • Browser/device used
    • All actions performed
  • Security Features:
    • Idle timeout: Logout after X minutes of inactivity
    • Session locking: Lock if suspicious activity detected
    • Concurrent sessions: Control how many devices logged in

🚪 D. Logout (End Session)

Logout Process:

  1. User Clicks Logout:
    • Click logout button in interface
    • Or automatic logout on token expiration
  2. Server Invalidates Session:
    • Clears user from security context
    • Invalidates user's session
    • Removes all session data
    • Token becomes invalid
  3. User Is Redirected:
    • Redirected to login page
    • All API access blocked
    • Must login again to access system

What Happens After Logout:

  • User cannot access any protected resources
  • Cannot view any data without logging in
  • All permissions revoked until next login
  • Logout recorded in audit trail

🔵 E. SAML/Azure Single Sign-On (SSO)

What is SAML/Azure Login?

  • SAML (Security Assertion Markup Language):
    • Enterprise authentication protocol
    • Uses identity provider (IdP) for authentication
    • Company's Azure AD or corporate IdP handles login
    • User never enters password in our system
  • Benefits:
    • Single password across all company systems
    • Centralized user management
    • Better security (no password exposure)
    • Easier for corporate enterprises

SAML Login Flow:

  1. User Clicks "Login with SAML":
    • Redirected to company's identity provider
    • User logs in with corporate credentials
    • IdP verifies user identity
  2. IdP Responds with Assertion:
    • IdP creates SAML assertion (signed XML)
    • Contains user's email, name, groups
    • Sends assertion back to our system
  3. System Verifies Assertion:
    • Check signature is from trusted IdP
    • Extract email from assertion
    • Validate email exists in our system
  4. Generate Token:
    • User authenticated successfully
    • Generate JWT token for this user
    • User logged in with same experience

Azure AD Integration:

  • System supports Azure AD SSO
  • Uses email from Azure to find user account
  • Creates token with user's roles and permissions
  • No separate login needed if already in Azure

✅ F. Token Validation on Every Request

How Token Validation Works:

  1. User Makes API Request:
    • Client includes token in request header
    • Token format: "Bearer {token}"
    • Sent with every API call
  2. Server Receives Request:
    • Extracts token from request
    • Removes "Bearer" prefix
    • Passes token to validation
  3. Token Validation Checks:
    • ✓ Signature is valid (signed by server)
    • ✓ Token not expired (issue + lifetime)
    • ✓ Claims are valid (user ID, org ID)
    • ✓ Not malformed (valid JWT structure)
  4. Validation Result:
    • If valid: Process request normally
    • If invalid: Return 401 Unauthorized error
    • If expired: Return 401 "Token expired"

Validation Errors:

  • Signature Exception: Token was tampered with, access denied
  • Expired JWT Exception: Token expired, user must login again
  • Malformed JWT Exception: Token format invalid, access denied
  • Unsupported JWT Exception: Wrong token algorithm, access denied

👤 2. User Management

2.1 User Creation Process:

  1. Admin creates new user account in system
  2. Assigns unique email address (login identifier)
  3. Sets initial password or sends invite link
  4. Assigns role (Admin, Manager, User, Data Entry, etc.)
  5. Selects department/team assignment
  6. Sets cost center for expense tracking
  7. Defines approval limits (if Manager/Approver)
  8. Account becomes active, user can login

2.2 Role Assignment & Hierarchy:

  • System Admin: Full access to all modules, can create/edit users, system configuration
  • Manager/Approver: Can view team data, approve requisitions, set limits
  • Data Entry: Can create and edit records within assigned module
  • Viewer: Read-only access to specific modules
  • Role can be changed anytime, changes take effect immediately on next login

2.3 Permission Matrix:

  • View: Can see existing records and reports
  • Create: Can add new records to module
  • Edit: Can modify existing records
  • Delete: Can remove records permanently
  • Approve: Can approve requisitions, purchase orders, requisitions
  • Export: Can download data to Excel/PDF
  • Module-Specific: Different permissions per module (Sales, Purchasing, etc.)

2.4 User Status Management:

  • Active: User can login and access system
  • Inactive: User cannot login, all sessions terminated
  • On Leave: Cannot login during specified dates, approvals delegated
  • Archived: Historical user, cannot login, data retained for audit
  • Status can be toggled without deleting user data

2.5 Password & Security Management:

  • Initial Setup: Admin sends temporary password or reset link
  • Password Reset: Users can self-serve reset via email, Admin can force reset
  • Password Policy: Minimum length, complexity requirements, expiration rules
  • Failed Login Tracking: System tracks failed login attempts, account locked after X attempts
  • Session Management: Auto-logout after inactivity period, simultaneous login prevention

2.6 User Profile Information:

  • Full name, Designation/Job Title, Department
  • Phone numbers (mobile, office), Email addresses (work, alternate)
  • Reporting Manager, Cost Center for expense allocation
  • Date of joining, Employment type (Full-time, Contractor)
  • Approval authority level (e.g., can approve up to $10,000)
  • Skills/competencies, Languages spoken

2.7 User Activity & Audit Trail:

  • Track every user login/logout with timestamp
  • Record who created/edited/deleted each record
  • View activity history: what user did, when, and from which IP
  • Identify suspicious activities (multiple failed logins, after-hours access)
  • Generate compliance reports for audits

2.8 Multi-Role & Delegation Features:

  • User can have multiple roles simultaneously
  • Example: John is both "Sales Manager" and "Approver"
  • Delegation: Manager can delegate approval rights to another user during absence
  • Acting As: Approver with higher limit can act as lower-level approver if needed
  • Holiday Calendar: Mark user as unavailable, auto-route approvals

Customer Creation Process:

  1. Sales user creates new customer
  2. Enters customer name (business name)
  3. Adds address (street, city, state, country)
  4. Adds contact details (phone, email, fax)
  5. Assigns Customer Relationship Manager
  6. Sets industry type (optional)

Customer Information Stored:

  • Basic Info: Customer name, Industry, Website, Created date, Modified date
  • Address: Street, City, State, Country, Postal code
  • Contact: Phone, Email, Fax
  • Management: Customer Relationship Manager (assigned user)

Customer Status Management:

  • Active: Customer available for sales orders and quotations
  • Inactive: Delete → Customer marked Inactive (data preserved, not deleted)
  • On Hold: Temporary pause (e.g., payment issues)
  • Archived: Permanently closed, data retained for compliance
  • Example: Delete ABC Corp → Status becomes Inactive → Cannot create new orders → Historical data preserved

🎯 B. Job Number Management

Job Number Creation:

  1. Project manager receives customer request for custom work
  2. Creates new Job in system
  3. System auto-generates unique Job Number (e.g., JOB-2024-001)
  4. Selects customer for this job
  5. Sets Job Type (Repair, Manufacturing, Service, etc.)
  6. Enters project description and scope
  7. Sets Start Date and Expected End Date
  8. Sets Budget (maximum spend on this job)
  9. Job created in Active status

Job Number Details:

  • Core Info: Job Number, Customer name, Job Type, Description
  • Timeline: Start date, Expected end date, Completion date
  • Financial: Budget allocated, Spent so far, Remaining budget
  • Team: Project manager, Team members assigned
  • Status: Active, On Hold, Completed, Archived

Job Status & State:

  • Active Job: Work in progress, costs being charged, team can log hours/materials
  • On Hold: Paused, no costs charged, waiting for customer decision
  • Completed: Work finished, final costs calculated
  • Inactive/Archived: Old closed jobs, data retained for records

Budget Tracking & Cost Control:

  • Budget Set at Creation: "This job has $50,000 budget"
  • All Costs Tracked: Materials → charged to job, Labor → charged to job, Subcontracting → charged to job
  • Real-Time Visibility: Dashboard shows budget vs actual
  • Budget Status: On Budget, At Risk (80%+ spent), Over Budget
  • Alerts notify if job going over budget

Job Hold Feature:

  • When to Hold: Waiting for approval, Payment pending, Material shortage
  • On Hold: No new costs, No materials issued, No hours logged
  • Resume: Once resolved, Manager clicks "Resume", Work continues

Job Revisions & Change Orders:

  • Original Job: "Paint building - $100,000"
  • Customer adds: "Also paint roof" → Create Revision 1 → Budget $150,000
  • Each revision tracked separately with its own budget
  • Full audit trail of all changes

📑 4. Masters Module (Configuration Data)

🏭 A. Manufacturers

📝 Create New Manufacturer:

  1. Go to Masters → Manufacturers
  2. Click "Add New Manufacturer" button
  3. Enter Details:
    • Manufacturer Name (e.g., "Bosch", "Sony", "Siemens")
    • Website URL (optional)
    • Address: Street, City, State, Country
    • Contact Person Name
    • Phone Numbers (Primary & Alternate)
    • Email Address
    • Quality Rating (1-5 stars)
    • Notes (any special information)
  4. Click "Validate" to check for duplicates
  5. Click "Save" button
  6. Manufacturer created successfully

👁️ View Manufacturers List:

  • Go to: Masters → Manufacturers
  • Displays: Table with all manufacturers and their details
  • Columns Shown: Manufacturer Name, Website, City, Contact Person, Quality Rating, Status
  • Search: Use search box to find specific manufacturer by name
  • Filter: Filter by status (Active/Inactive) or quality rating
  • Sort: Click column headers to sort by name, city, rating, etc.
  • Pagination: View records in pages (10, 25, 50 per page)

✏️ Edit Manufacturer Details:

  1. Go to Manufacturers list
  2. Find the manufacturer to edit
  3. Click "Edit" button/link on that row
  4. Editable Fields:
    • Website URL
    • Address (Street, City, State, Country)
    • Contact Person
    • Phone Numbers
    • Email
    • Quality Rating
    • Notes
  5. Cannot Edit: Manufacturer Name (locked), ID (system-generated)
  6. Make changes
  7. Click "Update" to save changes
  8. System shows confirmation message
  9. Changes reflected immediately in all forms using this manufacturer

🗑️ Delete/Deactivate Manufacturer:

  • Method 1 - Soft Delete (Recommended):
    • Select manufacturer from list
    • Click "Deactivate" button
    • Status changes to "Inactive"
    • Data is preserved (not deleted)
    • Cannot select in new forms, but historical records remain
    • Can be reactivated later if needed
  • Method 2 - Hard Delete:
    • Only available if manufacturer not used in any items
    • If used, system shows error: "Cannot delete - used in X items"
    • Must deactivate and leave historical records

📊 Audit Trail:

  • View History: Click "View History" on manufacturer record
  • Tracked Changes: Who created, when created, who edited, what changed, when changed
  • Example: "John created Sony on Jan 1 → Sarah updated phone on Jan 15 → Mike deactivated on Feb 1"
  • Compliance: Full audit trail for compliance and troubleshooting

📊 Common Units & Usage:

  • PCS (Pieces): Individual items - screws, bolts, fasteners
  • KG (Kilogram): Weight-based - iron, steel, raw materials
  • LTR (Liter): Liquid - oil, paint, chemicals
  • MTR (Meter): Length-based - cloth, wire, cable

  • SQM (Square Meter): Area - carpets, sheets
  • CU.M (Cubic Meter): Volume - concrete, sand

How Units Are Used:

  • Every item has a unit (e.g., "Steel Rod - KG")
  • Quantities in orders specified in item's unit
  • Example: Order "50 KG Steel" not "50 pieces Steel"
  • Inventory reports show quantities in correct units
  • Prevents ordering wrong quantities

    • ON_SCHEDULE_VARIANCE: When job falls behind schedule
  • Condition-Based Rules:
    • Trigger rule only if conditions met

🔢 G. Job Number Format (Auto-Generate Job Numbers)

🔢 Define Job Number Format:

  • Go to: Job Lifecycle → Job Type → [Select] → Job Number Format
  • What is Job Number Format?
    • Template for automatically generating unique job numbers
    • Each job type can have its own format
    • Examples:
      • MFG-2024-00001 (Prefix - Year - Sequential)
      • WR-JAN24-0001 (Type - Month - Counter)

📋 Format Components:

  • Available Format Tokens:
    • {PREFIX}: Fixed text (e.g., "MFG", "WR", "INS")

    • {SEQUENCE}: Auto-incrementing counter (0001, 0002, ...)
    • {JOBTYPE}: Job type code
    • {DEPARTMENT}: Department code
  • Example Format: MFG-{YEAR}-{SEQUENCE}
    • First job in 2024: MFG-2024-0001
    • Second job in 2024: MFG-2024-0002
    • First job in 2025: MFG-2025-0001 (sequence resets annually)

  • Manual Generation:

  • Reset Sequence:
